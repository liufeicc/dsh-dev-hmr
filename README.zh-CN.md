# dsh-dev-hmr

开发用配置型 bundle：把 base bundle 里那行 `id: hmr`（`@deepseek-ai/dsh-hmr`）的
`config.root` 从 `[]` 改成监听插件源码目录，从而**保存插件文件即热重载宿主插件**，
不必重装、不必重启宿主。

## 为什么需要它

base bundle 自己的 hmr 行把 `root` 显式设成 `[]`。按 `dsh-hmr` 的 README，
`root: []` 只保留「显式配置监听」，**不监听模块源码**。实测后果：

| 动作 | 旧代码是否被替换 |
|---|---|
| 直接改已加载插件的 `.js` | ❌ 不重载 |
| 改 `package.json` 的 `exports` 指向新文件后 `remove_bundle` + `install_bundle` | ❌ 仍跑旧代码（Loader 按**包名**缓存模块） |
| 换成**新包名**（新建包目录）再装 | ✅ 跑新代码（但脏） |
| **本 bundle 生效后**，直接改源码保存 | ✅ 热重载（已验证） |

所以没有它，迭代宿主插件只能靠"每次换包名"或"每次重启宿主"。

## 生效验证（2026-10-13，实测）

用一个只写标记的一次性金丝雀插件验证：

```
v1 2026-10-13T05:27:58.366Z pid=29419
v1 disposed 2026-10-13T05:28:14.609Z     ← 旧模块卸载
v2 2026-10-13T05:28:14.618Z pid=29419    ← 新代码接管，同 pid 未重启进程
```

## 配置语义（改这个文件前必读）

- 这是**同 id 覆盖**（不是 `insert`）。按 Loader patch 方言：
  - `config` 是**整体替换、不做深合并** —— 没写的字段退回 schema 默认值。
    这里刻意只写 `base`/`root`，让 `ignored` 用默认的
    `["**/node_modules", "**/.*", "cache", "data"]`（正好排除 `dsh-desktop` 那个
    266M 的 `node_modules`）、`debounce` 用默认 100ms。
  - `name` 在这里是**断言**目标行，不是改名。
- `base` 取 `dsh/` 父目录、`root: ["."]`：一次覆盖所有插件目录，
  以后新建插件包不用再改配置（改配置很可能又要重启一次宿主）。
- 关掉热重载：`remove_bundle` 本 bundle，即回到 base bundle 的 `root: []`。

## 代价与注意

- 监听整棵 `dsh/` 插件树（不含 node_modules）。保存**任何**插件文件都会重载那个插件，
  包括别人/别的会话正在改的。
- 重载会改变工具集与提示词，可能让 prompt cache 从变化处失效 —— 开发期可接受。
- 浏览器端的客户端插件是**另一套**加载机制，不受这里影响。
